# CLAUDE.md

FamilyDB is a family planning chat bot: Python 3.11+, SQLite, a model from Anthropic, OpenAI or Google behind one provider protocol, Telegram and the web page as chat channels, and a web surface for browsing, editing, status and settings. Design: `docs/DESIGN.md`. Server setup: `RUNBOOK.md`, `docs/INSTALL.md`.

## How to read the rules

Rules here exist so a change does not quietly cost money, break the prompt cache, open a hole, lose a message, or undo a choice the family made on purpose. Each says why; most are held by a test. They are not a list of what may not be tried: a rule that blocks a better design is changed in the same PR, with its reason, rather than worked around. When a rule and its reason disagree, the reason wins. Four kinds:

- **Invariants** (cost, cache, security, delivery): a test holds each; the test changes with the rule, never quietly.
- **Design and feel** (look, layout, wording, pages, how Vera appears and sounds, what scripts do): open; evolve freely, including by AI agents. `docs/STYLE.md` records the look and why; update it in the same change, and the tests that pin today's markup. Floors that do not move: accessibility, the content security policy, escaping, no model call for a page view, and the evals when her character or prompt changes.
- **The family's decisions** (`docs/DESIGN.md` section 16; shared location section 10; spending section 14): who may message the bot and who signs in, what leaves the house, what may be spent, what each role may do. Changing one means asking them and saying what it costs or gains.
- **Defaults** (one module per tool group, one repository per table, the page's wording in `web/views.py`): follow unless there is a reason, and say it.

## Token economy

- Paid inference is limited. Prefer local deterministic code; minimize total cost per successful task (input, output, reasoning, cache charges, tool searches, retries). Measure tokens, not characters. GPT-6 Luna is the default for chat and lookups for that reason.
- Human replies are terse. Machine-facing messages carry only necessary validated structured fields, with provider schema correctness preserved.
- Memory rides on the chat call: the `remember` tool (`tools/memory.py`) emits compact deltas, and its `reply` ends a turn that only remembered. No routine background extraction call, paid retrieval, or follow-up call to acknowledge persistence. Storage, dedupe, expiry, indexing and retrieval are local; `familydb/memory.py` picks what each message is sent, in the uncached current turn, firm ones always. Design and acceptance: `docs/MEMORY.md`. `/memory` shows and forgets it.
- Bound calls, tool iterations, context, output and retries. Choose the cheapest configured model that meets measured quality.
- The daily spending limit (`agent/spending.py`) is checked before every call (in the loop per call, and in `gateway.listen` for a voice note). Cost is estimated from `agent/providers/prices.py` and stored in `llm_calls`; prices in force are the daily check's (`familydb/model_watch.py`) laid over the built-in table by `prices.use`. A model neither knows is counted dearer than any listed, so add a price when adding a model worth suggesting. It is an estimate, not the bill.
- Every kind of model call decides, sees, acts and is trusted as framed in `docs/AI_CALLS.md` (code knows, the model understands and words). A new kind answers its five questions before it is on by default.
- Kids' wish lists: `docs/WISHES.md`. Persona (changes how things are said, never what is done): `docs/PERSONAS.md`.

## Commands

- `uv sync`; `uv run familydb --help`. Tests: `uv run pytest -q` (no network; provider SDKs faked in `tests/fakes.py`; the shared `settings` fixture pins Claude). Lint: `uv run ruff check . && uv run ruff format .`.
- Live (need `ANTHROPIC_API_KEY`): `FAMILYDB_LIVE=1 uv run pytest -m live`, `uv run familydb debug validate-tools`.
- Evals against a real model (cents a run): `uv run python -m evals` (`--repeat 3`, `--provider` with `--model` or `--level`, `--persona KEY|none|FILE`, `--case NAME --show`). Cases in `evals/cases.py` are the family's own requests, graded by code on what was called, saved and said. Run before and after changing a prompt, tool description or model. A case that stops holding is a regression or encoded the old behaviour; update it with the reason.
- Jobs by hand: `familydb enrich --idea N`, `suggest --window this-weekend [--discover]`, `digest --now`, `follow-ups --now`.
- Web: `WEB_PASSWORD=test uv run familydb web --port 8099` (pages: `/`, `/chat`, `/ideas`, `/plans`, `/tasks`, `/family`, `/status`, `/settings`). Calendar is read only through `app.calendar` (`recent_events`, cached a minute unless the bot wrote); with none configured it shows saved plans.
- `familydb config` shows each setting and its source. `familydb debug prompt --as Sam "..."` (or `--kind enrich --idea 57`) shows a request built by the same code that sends it. `familydb debug cost` for cost.
- Dependabot opens monthly PRs; SDK floors in `pyproject.toml` are the tested versions; raise with `uv lock`.
- Install: the one block in `docs/INSTALL.md` step 1 runs `scripts/bootstrap.sh` then `scripts/install.sh` (asks at most for a domain, writes `.env`, installs, migrates, puts Caddy HTTPS in front on 443 or `WEB_PUBLIC_PORT`, schedules backups; Docker or virtualenv). Every failure says what to do and that rerunning carries on (`again_hint`). `maintain.sh https --port N|random` moves the public port, `maintain.sh port N|random` FamilyDB's own `WEB_PORT`. `scripts/uninstall.sh --from-zero` removes everything after two confirmations. Configuration the family would change belongs on the settings page (a line in `store.settings.BEHAVIOUR` and `web/fields.py`), and a setup step (`web/status.setup_progress`, `web/setup.py`) if the bot is unusable without it; the installer writes such a value only when given in the environment. Operator-only knobs may stay in `.env`.

## Layout

- `pipeline.py`: one inbound message end to end; channels call `handle_incoming`. Telegram with `gather_seconds` calls `receive` (store now, held under `delivery.GATHER`) then `answer_gathered` (defers to a newer message from the same person in the same chat, else answers all their waiting messages in one turn and one reply, claimed via `delivery.claim_also` and folded in with `messages.fold_into`). Turns in one chat run one at a time per process (`_one_at_a_time`). A voice note (`channels.base.VoiceNote`) is stored as a mark (`messages.unheard`), heard under the message lease through `gateway.listen`, and its words replace the mark after `VOICE_PREFIX`; unhearable ones are given up with a `voice_*` line (recording never kept). A photo (`PhotoNote`) likewise through `gateway.look` (`prompts/look.md`, `PHOTO_PREFIX`, `photo_*`).
- `delivery.py`: message leases (expiring claims, renewed while a turn runs) and at-least-once delivery of stored replies. `calendar_sync.py` aligns plans with their Google events in one request (sync token in `calendar_sync_state`). `agenda.py` reads what is on (Google, else saved plans); `free_time.py` computes event days and free stretches.
- `family.py`: add/change/remove members (birthday → age in code; for kids male/female set by an admin, only age reaching the model; what `remove` takes with it is `store.members.POINTING_AT`, which a test holds to the schema, so a new table pointing at a member must say), sign-in, Telegram linking by one-time admin-made link (`invite`, `accept_invite`, hashed in `telegram_invites`). `roles.py`: admin, parent, kid and their permissions. `task_service.py`: task and reminder changes for tools and the reminder job (repeats on schedule or from last done, in family wall time; birthdays list gift ideas). `wish_service.py`: wish-list rules for tools and page (`docs/WISHES.md`). `windows.py` reads a task's preferred window in code from a short word list. `presents.py`: whom a present (an idea of kind gift; any way of saying present is saved as gift) is kept from: every kid, always, and the grown-up it names unless somebody chose others (`ideas.hidden_from` holds only the grown-ups chosen; NULL is the default); to-dos about it (`tasks.idea_id`) go with it (`visible_tasks`); pages, chat tools and birthday reminders all ask it, and the model's idea record never carries the column.
- `commands.py`: Telegram /today, /week, /tasks, /now, /lookup by code, no model call; family only; stored processed so no turn takes it; the answer is her reply under a `voice.EVENTS` `cmd_*` heading. `buttons.py`: buttons under a reminder or follow-up and what a tap does: code calling the tool the model would have called, as the member who tapped, after checking the family list; no model call; the tap is kept as a message (`TAP_PREFIX`), said by `voice.EVENTS` `tap_*`; buttons are stored with the message (`messages.buttons`) and go through `App.button_senders`.
- `personas/`: a `Persona` is name, label, character and lines, one folder each (`default/` Vera, `brief/`): `persona.toml`, `character.md`, `lines.toml` (a line may be a list of wordings). `personas.active(settings)` is the one in force (`persona` setting; `PLAIN` for `none`; family overlays from `/settings/personality`: `persona_name`, `Settings.persona_text` as `PersonaRewrite` with `of`, `persona_notes`, `voice_lines`). Her name is written once, in `persona.toml`; character, lines and rewrites use `{name}`; the prompt, `voice.py`, Telegram and every page ask `personas.active`, nothing else works out who she is. Old keys still resolve (`personas.key_for`, `RENAMED`). Her character, then the family's notes, go first in the chat prefix, ahead of `prompts/system.md`; the job wins where they meet (`agent/prompt.py` `JOB_HEADER`). Workers never carry it.
- `voice.py`: every unprompted message is worded here. A line may have several wordings; `say` picks by CRC-32 of event and `seed` (message id) or facts, never chance, so a resend says the same words. `audience.py`: who reads a chat (kid's own, group with a kid, shared page), so workings are said plainly where a kid reads (`voice.PLAIN`, `plain=`) and presents listed only where everyone may decide. `routing.py` sends person-only messages (their reminder, nudge, idea note, plan outcome) to their own Telegram chat when it began in a group; `CONFIRMED` is the ✓ a group's "saved" is. `whereabouts.py`: where a phone said a member was, named once by reverse geocode, kept 3 hours of use and a day at most (`forget_locations` deletes). `privacy.py`: owner-only umask and tightening of older files.
- `agent/providers/`: one module per vendor behind a small protocol (`base.py` types; `anthropic.py`, `openai.py`, `gemini.py`). Each has `model_exists` (free), `listed_models`, maps a 404 for the model to `trouble="model"`, can hear voice (`listener`, `transcribe`; not Claude; `hearers` says who) and look at photos (`viewer`, `describe`; `lookers`). `prices.py` is SDK-free: built-in prices plus the daily check's (`use`, from `App.refresh`), model suggestions (`suggestions`), notes (`note`). Request shape is read from the model name; modules list older generations (`anthropic.OLDER_MODELS`, `gemini.OLDER_MODELS`), not the current one. `catalog.py` (SDK-free) is each company's lineup by level (everyday, better, best) and whether each thinks; `providers.model_at` picks a model per level, never cheaper than everyday; `gateway.KINDS` names per kind `chat_level`, `digest_level`, `lookup_level` (the retry job asks a failed digest again as `pipeline.DIGEST_UPDATE`). A model added to the lineup needs a price; a test holds the catalog to what the modules send. A vendor is one module and one name in `NAMES`; nothing outside this folder mentions an SDK.
- `agent/`: `gateway.py` is the one door to a model (`KINDS`: chat, digest, retry, enrich, discover, each with prompt, tools, web budget, limits and, for workers, `hand_back` tools whose success ends the turn; `ask`, `listen`, `look`). `compose.py` builds requests from labelled parts and records their sizes per call. `prompt.py` renders the chat prefix, `history.py` the chat, `loop.py` is the manual tool loop, `worker.py` the small web-capable turns (`prompts/enrich.md`, `discover.md`), `prompts/system.md` the product spec for the chat model.
- `judgement.py`: code files a question when a change needs weighing (`file_replacement`, `file_lineup`, `file_price`, `file_refused`), kept in `judgements`. The `judgements` job (every 15 min; no model call when nothing is due or `judgements` is off) asks the day's questions together after `lookup_hour`, a refusal at once, in one `judge` call at `judgement_level` within `judgement_budget` a month; a disputed price goes to a `price_check` worker with the web. What the model hands back (`tools/judgement.py`: `give_judgement`, `report_price`) must be one of the options and code acts: under `judgement_acts` "within_cost" a model costing at most `SAME_COST` times the old one is saved (source "judgement"), dearer waits; buttons under Models and prices on Status; admins told (alert `advice`). Family-named better/best models (`<company>_better_model`, `_best_model`) answer at those levels.
- `tools/`: `registry.py` declares and dispatches; one module per group. `places.py` (place cache; `look_up_now` asks for lookup on the next run, refused to anybody who may not `change`, so a kid's wait for the evening), `suggest.py` (`suggest`, `report_finds`), `tasks.py`, `wishes.py` (`add_wish`, `update_wish`, `turn_away`; a kid's message carries her age, her wish topics where only she reads, and whether to nudge wording via `familydb/wording.py`, by code, at most daily).
- `suggest/`: the engine as code, one module per stage (`context`, `shortlist`, `evaluate`, `discover`, `compose`, `log`) behind `engine.run`. The model frames the question and words the reply; verdicts and reasons come from code and are logged to `suggestions`. Time is minutes: each day's free stretches between bounds (08:00-22:00 unless a part of the day is named, "now" from this minute); never reason in morning/afternoon/evening there.
- `store/`: `db.py` (connection, transactions, JSON, migrations), `migrations/*.sql`, one repository per table returning pydantic records. `logins.py` keeps password hashes apart from `members` so a hash never reaches the prompt. `settings.py` is what the page writes: `BEHAVIOUR` and `SECRETS` are the whitelist.
- `channels/`: message dataclasses, console, Telegram (text, voice, photos; Telegram HTML from the light Markdown models write via `markup.py`, falling back to plain; `asyncio.to_thread` into the sync pipeline; `TelegramSupervisor` follows the token setting and keeps the bot's name and description in step, no model call) and web (`WebChat` runs a turn on its own thread so the form post answers at once).
- `web/`: Flask factory over an `App` (`__init__.py`); `auth.py` the sign-in gate (`Visitor`, CSRF, `refused()`), `once.py`, `routes.py` reading views and the manifest, `shell.py` (the frame's health pill, nav counts and who is signed in, asked by `base.html`), `status.py` (the page's data, and `health` and `verdict`, which the page's top line and its rows are built from; the pill is `pill`), `activity.py` (one message's or lookup's full history for admins, by message or `turn` id), `chat.py` (page and the Home box; `glance`, `standing` from the log, no model call), `edits.py`, `family.py`, `look.py` and `looks.py` (a person's look, kept with them in `members.look` through `family.choose_look` and in a cookie for the pages before anybody signs in; looks are token blocks in `static/themes.css`, Kitchen Table the default), `settings.py` (a card per `fields.SECTIONS`, a page each), `setup.py` (`/setup`, one step at a time, progress read from what is configured by `status.setup_progress`, never stored), `fields.py` (pages, groups, boxes drawn from `Settings`, help text), `views.py` (wording helpers), `links.py` (every outside link; `familydb doctor --online` checks them). `wiki.py` serves the guide (`/wiki`, for `browse`, so parents and admins and never a kid): Markdown from `src/familydb/wiki/`, laid out by `_nav.json`, cached by mtime, searched on the server, with no model call and no table read; underscore-named files there (`_outline.md`, its backlog) are never served. `templates/` (`base.html` the frame, `_ui.html` shared macros, `_composer.html` the message box, `_settings.html`), `static/` (`style.css`, `themes.css`, `ask.js`, `wishes.js`, `dictate.js`, `fonts/`, `brand/` the favicons and home-screen icons, `icons.svg` the icon sprite, both the design's own and kept as files). Look and its rules: `docs/STYLE.md`.
- `integrations/`: Google Calendar, Open-Meteo, geocoder (Nominatim, Open-Meteo fallback; `GEOCODER_CONTACT` goes in the User-Agent), public price lists (`price_lists.py`, LiteLLM's and OpenRouter's; tests never fetch), the clients behind small Protocols where they have one; tests use `tests/fakes.py`.
- `jobs/`: APScheduler `BackgroundScheduler`; each job's schedule is described once in `scheduler.job_specs`; jobs open their own connection (`app.connect()`) and reply through `app.senders`. Idle path calls no model. `enrich` (a worker turn per idea due; by default lookups wait for evening, `lookups_when`, `lookup_hour`, one run, one note per chat; `look_up_now` ideas run next; "asap" looks up each as it comes), `weekend_digest`, `follow_ups`, `plan_checks` (daily at `plan_check_hour`: the evening before a plan, rain for outdoor or place closed gets a heads-up with a backup from the engine; nothing otherwise), `reminders` (every minute; queue and send once; failed sends are the retry job's), `forget_locations`, `model_watch` (daily 05:17; `familydb/model_watch.py` asks each keyed company which models it may use, reads both price lists via `price_lists.py`, takes a price only when both agree or one alone moves sanely, stores `models`, `model_changes`, `model_sources`, puts it in force, and notes for admins: a model in use gone or going with the nearest at about its price (`replacement`; it answers in its place once gone if at most `SWAP_DEARER` times as dear, `prices.swapped`, else only suggested, one press to put in), a moved price, a list failing three days running, lists at odds, new models; then `usage_watch.py` compares each kind of call's last week with the four before and notes big moves, once in seven days per kind; `model_watch` turns both off), `alerts` (every minute: tells each admin with a Telegram id what only an admin can fix, from the `alerts` table, kinds `alerts.KINDS`, filled by `familydb/alerts.py` where each trouble is seen: out of credit or key refused as read into `AgentError.trouble`, a refusal nobody can read (`refused`, told on the second, `TOLD_AFTER`), a request part left out (`api`), the day's limit in `spending.admit`, Google shutting the bot out via `GoogleCalendar.report`, `advice`; forgotten when it works again, re-told at most every 12h, listed on Status; `admin_alerts` turns off), `nudges` (every 15 min: a task kept for a window `windows.py` can read, when it comes round and the calendar is free; each once a week, one a day per chat; `task_nudges` turns off), `catch_up` (after restart), `settings_watch`.

## Rules that keep it working

- Nothing volatile in the cached prompt prefix: tools, system prompt, family context and idea list contain no dates, times, sender or per-request ids; those go in the current user turn (`render_user_turn`). The family's `about_family` goes in the family context (changes only on edit). Where a member is (`render_location_line`, only while fresh) and who reads the reply (`render_audience_line`: shared chat says everyone there reads it, and whether kids are among them; private chat none) go in the turn too. The family chose to send location: the chat model and discovery worker get place name and coordinates.
- Rendering is deterministic: idea lines, JSON (`store.db.to_json`, sorted keys), tools sorted by name, server tools last.
- Every tool is always declared to the model that may call it; the list never varies between turns (it would cost the cache). Availability is checked at dispatch; unavailable returns `{"available": false, ...}` as a non-error result so the model reports the skipped check. `worker_only` tools are left out of the chat list. Dispatch refuses a tool not declared for the turn, and an enrichment turn may only write to its own idea (fetched pages can talk a model into naming any tool). Tool input models use `Literal` and handler checks, not numeric or length constraints (strict schemas strip them).
- Tokens are the running cost: before adding to the cached prefix or a scheduled job that calls the model, check `familydb debug cost`; every job must read the database and return without an API call when idle. Code running the suggestion engine with no model call (commands, evening check) passes `refresh_stale=False`.
- One SQLite connection per thread. Writes inside `store.db.transaction`. Tools own their transactions so partial progress survives a failed turn. No transaction open around a worker turn (its loop writes audit rows). Discovery results live in `App.discover_cache` keyed by window; failures never cached.
- Migrations are append-only numbered files; never edit an applied one. Schema changes to FTS-indexed columns need an FTS rebuild in the migration. Next is `0044`. A migration rebuilding a table other tables point at starts with `-- foreign_keys: off` (honoured by `db.migrate` around its transaction) and checks its own work before commit, as `0018` does. `0007` is reserved and never used (`tests/test_migrations.py` knows the gap).
- The core is synchronous; async adapters (Telegram) use `asyncio.to_thread`; anything sending from another thread uses the channel's thread-safe sender.
- Tools reach services only through `ToolContext.calendar` and `ToolContext.weather`, so they stay testable with fakes.
- Everything the bot says of its own accord is worded by `voice.say`, never a literal at the call site; a new kind of message is a line in `voice.EVENTS`. A proactive message goes out through `voice.hand_over`, which keeps its kind (`messages.sent_as`; the digest's reply is kept as `digest`), so the Messages page lists each kind (`web/status.automatic`, `views.AUTOMATIC`: a new kind is a line there). It holds a message a moment while the family is talking so the next reply carries it (marked delivered with that reply); the minute job sends what no reply carried. No model call is made to word one. Where a kid reads (`audience.plain`), workings are said as the `voice.PLAIN` line: kids never see how the bot works or why it does not (a family decision, `docs/DESIGN.md` section 16; `tests/test_kids_plain.py`, `test_a_kid_is_never_shown_how_it_works`).
- A reply is stored before it is sent and marked delivered only after the send succeeds: anything that sends goes through `delivery.deliver`. Anything working on an inbound message holds its `lease`, so a restart strands nothing and two workers never answer one message; a message waiting to be answered with later ones is held under `GATHER`, which only a turn answering it may take over and which lapses to the retry job.
- The loop knows nothing about any vendor: it builds a provider-neutral request and reads a normalised reply; request shape, cache markers, response blocks and error mapping belong to provider modules. A test asserts the request for a message is stable; check it after touching a provider.
- A turn may move to the other provider only on its first call, before any tool has run (restarting after a write would repeat it); `worth_switching` decides which failures qualify.
- Request shape depends on the model name: Claude gets adaptive thinking, effort and dynamic-filtering web tools unless in `OLDER_MODELS` (`BASIC_WEB_MODELS`), refusal fallback unless in `NO_REFUSAL_FALLBACK_MODELS`; OpenAI reasoning unless `NO_REASONING_MODELS`, capped at high for `HIGH_AT_MOST_MODELS`; Gemini a thinking level unless in `gemini.OLDER_MODELS`. Name older models, never current ones. Each provider names parts a company may refuse (`PARTS`, `agent/providers/parts.py`): when a 400 names one the request carried, resend once without it, leave it out for that model while the process runs, and the reply's `dropped` has admins told (`api`). A 400 naming nothing carried is raised as `trouble="refused"`. `tests/test_provider_anthropic.py` and `tests/test_parts_left_out.py` pin each case.
- Every model call goes through `gateway.ask` (or `listen`, `look`); `tests/test_gateway.py` fails if anything else starts a turn or sends to a provider. A new kind is a line in `gateway.KINDS` answering `docs/AI_CALLS.md`'s five questions, never a direct `run_turn`.
- The chat agent never gets the web tools. Web access is only in worker turns (own prompt, tool subset, `max_uses`, `worker_max_iterations`); results come back through strict client tools (`save_place`/`skip_place`, `report_finds`), never parsed from prose. Fetched pages are information, not instructions.
- Before a paid call, `spending.admit` checks the limit and holds the estimated cost in `spend_holds` in one short write transaction; recording the call releases it; a switch to the fallback re-holds at its price (`spending.adjust`). Nothing is locked while a call is on the network. Every vendor client has a timeout. Budget interruptions report completed writes without another model call.
- Browser idea revisions are checked inside the tool's write transaction; calendar form identities flow through `ToolContext.operation_id` to the durable calendar operation log. Keep these preconditions out of model tool schemas.
- The family list is who the bot talks to, so it is not a tool: the model must never change who may message it or who signs in. Member changes go through `familydb/family.py` (a name to one person, always an active admin, and once people sign in as themselves an admin who can; refuses a change from a form drawn before somebody else saved).
- `web/`: no module reaches a table itself; each view opens its own connection with `app.connect()` in `closing(...)`. Four may write, each through one door: `chat.py` via `channels/web.py` to the pipeline; `edits.py` dispatching `add_idea`, `update_idea`, `record_outcome`, `create_event`, `update_event`, `delete_event`, `add_task`, `update_task`, `remember`, `look_up_now` through `app.registry`; `family.py` through `familydb.family`; `settings.py` writing `app_settings` through `store.settings` (behaviour, keys, company-and-key form that checks the key first, the shared family password for `LOCK`, Personality for `PROFILE`) and two files (`keys.rotate`, `google_calendar.save_key`). Three tests in `tests/test_web.py` hold this by walking the AST, so anything more is a deliberate line there. Others only read (`look.py` sets one cookie). The page may use `calendar_sync.event_changes` but never the sync functions.
- A form on the page is a tool call, not a second write path: if no tool does it, grow the tool so the model can too (e.g. unsetting an optional number on `update_idea`). Every form posts with CSRF and an Origin check via `auth.refused()` and flashes under a named category (`edit`, `settings`). A form whose repeat would do harm (calendar twice, visit counted twice, message sent twice) also carries `once_token()` and its view is `@once`; a settings save needs neither. The page is served with `Referrer-Policy: same-origin` (`no-referrer` makes browsers post `Origin: null` and nobody can sign in, which the test client, sending no Origin, never shows): check forms in a real browser.
- Behind a proxy, forwarding headers are waitress's business (`web/server.proxy_options`), not Flask's: waitress strips them from untrusted peers before the app runs, so a Flask middleware sees nothing and every sign-in fails the Origin check. Flask's test client skips waitress, so proxy behaviour is tested through a real server on a thread (`tests/test_web.py`).
- Scripts come only from the page: CSP is `script-src 'self'`, never `unsafe-inline`, no inline script; `style-src 'self'` allows no inline style, so styling lives in `static/style.css`. Scripts are a design choice; what must work with them off is reading, every form and sending a message. Today: `wishes.js` drags wishes by their grip; `dictate.js`, loaded only while `web_dictation` is on, adds a mic to fields marked `data-dictate` using the browser's own speech recognition (no model call, nothing sent until the form's button; sound goes browser → its maker, never through FamilyDB: family decision, `docs/DESIGN.md` section 16); `ask.js` keeps an unsent message in the tab's session storage (restored when the box returns empty, forgotten once the thread shows it arrived or the tab closes), fills the box from the ways to start, and sends the phone's position while "Send where I am" is ticked (off until ticked; the server keeps no position without it). The chat page waits for its answer with a `<meta http-equiv="refresh">` emitted only while a turn really runs and never on a page holding words somebody typed (the box is closed while a turn runs; while waiting on the retry job the box stays open and the script looks again only while nobody is writing; the meta refresh is in `<noscript>`). Templates escape by default; never mark anything from an idea, place or fetched page as safe.
- A setting can change from the page, so nothing may cache one, the Telegram token included. `App.refresh()` is called at every entry point (message, job, page view, scheduler tick) and rebuilds `App.settings` when stored values moved; read `app.settings` rather than holding it, and anything built from it goes in `App._forget_built`. Adding to `store.settings.BEHAVIOUR` also means a line in `web/fields.py` in the group of its page with help written for the family; tests check every setting is on exactly one page.
- An API key is write-only: stored, never rendered into a form, never written to the change log, shown only after the signed-in password is typed again.
- Setup is the page's job: `/setup` walks a new install through; each form already exists and posts to its owner with a `then` that may only name a `/setup` page (`auth.setup_return`). Home sends there until somebody is on the list and a model works. A new must-configure thing is a setup step.
- Each person signs in as themselves: name and own password, stored only as a hash in `member_logins` (`passwords.py`, `store/logins.py`, rules in `familydb/family.py`). Three roles (admin, parent, kid) and one permission table in `familydb/roles.py` (sign in and read ideas and plans, chat, change, browse household pages and everybody's tasks, keep a wish list, decide on wishes, manage). A kid may sign in, chat and keep her own wishes, sees only her own tasks, within `kid_daily_messages` a day for `roles.DAILY_LIMITED` (counted from `llm_calls`, so commands and buttons cost none; checked in `pipeline._run` before anything is heard or asked; reply `voice.EVENTS` `kid_limit`). The page asks `visitor().may(permission)`, never a role: `auth.NEEDS` gives each blueprint's permission, `auth.NEEDS_HERE` exceptions. An admin gives others a made-up starting password, shown once (held in memory, never in the session cookie, which is signed not sealed); the gate lets that person nowhere but `/you` until they choose their own, and changing your own asks for the current one unless it was a starting one. Each session carries a mark of its password, so a new one, being switched off, losing it or a role that may not sign in signs that person out everywhere. Chat and edit forms act as whoever is signed in, never a name the form sends. `familydb password [NAME]` makes a starting password on the server (the first admin unless named). Until an admin has their own, the page takes a shared password (`WEB_PASSWORD`, or one chosen on settings as `store.settings.LOCK`); the first admin's own (`family.claim`) ends it, and the last admin who can sign in can never go, so it never returns.
- The guide (`src/familydb/wiki/`) is what people read to understand and run it: a change to a setting, job, tool, role, page, command or default updates the page that names it in the same change, and the developer documents stay the source of truth for exact commands and reasons, which the guide summarizes and links rather than copies. `tests/test_wiki.py` holds the nav to the files and every link and anchor to a page, and keeps inline script and style out of a page (a Markdown table's centred column is one).
- Web wording lives in `web/views.py`, never `agent/render.py` (which feeds the cached prefix). No page view is a model call: Home and the chat read the log and word their own lines; only a sent message is a call (`test_browsing_asks_nothing_of_a_model`).
- Vera is who the family talks to; the page names her via `personas.active(settings).name` (`assistant` in every template). How she appears is design: today never drawn, and where she appears it is her screen of unreadable glyphs (`presence` in `_ui.html`); the smiling mark is FamilyDB's. `docs/STYLE.md` (principle 9, "Her screen") says why; weigh it before changing.
- Keep replies short. A change in behaviour is often cheapest as a line in `prompts/system.md`; when code is the better place (anything code can know), change the code.
- Every PR is reviewed before merge, however large; separate concerns in separate commits.
